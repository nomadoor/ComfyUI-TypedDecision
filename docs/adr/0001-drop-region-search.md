# Region Search を持たない

画像を四分木で分割しながら typed decision を繰り返し、条件の成り立つ領域を探すノード（Region Search）は、試作して破棄した。タイルだけを切り抜いて判定すると、深い段で文脈が消える。上の段の画像を一緒に見せれば形は取れるが、1 回の判定が重く、実用の時間に収まらない。領域を探すのは、セグメンテーションのモデルに任せる。

## Considered Options

計測は d3-mini int8、12 GB の GPU、5 段、閾値 0.3 → 0.5 で行った。

- **タイルだけを判定する（最初の実装）**：人 0.3%（手だけ）、鹿 0.1%（顔だけ）。切り抜くと「人」は手の断片になり、マスクが残らない。
- **上の段の画像と一緒に判定する**：上の段の画像には、次に拡大する範囲を赤枠で示した。人 5.1%、鹿 7.4% で、全体が取れた。
  - 時間は 81〜121 秒かかった。
  - 境界のタイルだけを割り、上の段の画像を 224px に縮めると、63〜75 秒になった。
  - d3-lite なら 23〜26 秒だが、鹿の胴が抜けた。
  - 1 回の判定に 0.15〜0.45 秒かかり、探索には 150〜350 回の判定が要る。この重さは Core の DeltaNet の prefill から来ていて、このパックでは変えられない。
- **親タイルを 2×2 の線で区切り、どのマスに写るかを choice で 1 回だけ聞く**：判定の回数は約 5 分の 1 になり、17〜23 秒で済んだ。ただ、人も鹿も頭が抜けた。
- **モザイク**：5 段のタイル（約 26px）は、モザイクの 1 ブロック（20px）とほぼ同じ大きさで、単色にしか見えない。

## Consequences

- `region.py` と Region Search ノードを外す。
- 位置を直接出せる typed decision のモデル（たとえば VideoJev の区間スコアの画像版）が使えるようになったら、作り直しを考える。
